## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Robustness] stale solncounter removed before each solve**
- `_execute_lsd` deletes an old `solncounter` in the output folder so a leftover from an earlier run cannot pose as this run's partial count. LSD rewrites the file each run.

**2. [Rule 1 - Bug] getversion contract**
- `get_version` returned "unknown" whenever LSD exited non-zero, which is always; now parses the banner. LSD gets `stdin=DEVNULL` in both places.

**3. Conversion failure keeps the old result fields**
- A fail-loud outlsd error still yields `success=False, solution_count=0, return_code=-1` (old contract); the new `found_count` carries the real count for the record, outcome "solutions" with absent reason "conversion_failed".

No other deviations. The wording LSD prints when MAXT stops it is not in the manual; the runner matches "time limit / maximum time / MAXT ... reached/exceeded" conservatively. This was not verified against real LSD output and should be checked in Plan 19 on Sheldon.
