<objective>
Turn the event log into the manifest (a pure reducer) and render the two Markdown views from it.

Purpose: REC-09 (manifest derived and rebuildable), REC-16 (declared, never inferred; stale on a
later solve), REC-12 (hook-less harnesses shown as "not recorded"), REC-13/D-09 (break marking),
REC-22 (reports are renderings). Fold and render are pure functions over dicts, so they need no
pydantic and can run in parallel with the models plan; they follow the payload keys fixed in
`ailsa.record.events.REQUIRED_PAYLOAD`.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent text in events → Markdown read by humans and agents | notes and prompts are untrusted strings |
| blind runs → renderings | renderings must not reveal identities in blind mode |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106.1-25 | Tampering | Markdown injection from agent text | mitigate | md_escape on every agent-supplied string; tested with pipes, backticks and `<script>` |
| T-106.1-26 | Spoofing | a run claiming success from agent files | mitigate | state derives only from final.declared events; hand-written files never change the state (golden test) |
| T-106.1-27 | Information disclosure | blind leak via renderings | mitigate | identity names hidden in blind runs; human prompt text not echoed in the diary |
| T-106.1-28 | Repudiation | edited log rendered as clean | mitigate | integrity line and break marker; counts_as_clean False whenever integrity is not clean (D-09) |
