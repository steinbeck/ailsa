<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dataset path / options → workspace | user- or agent-supplied paths decide where runs are created |
| earlier runs → new blind run | earlier answers in the workspace or the dataset could leak into a blind run |
| child process → host | the view export runs detached |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106.1-55 | Information disclosure | blind leak via prior runs | mitigate | fingerprint-based prior-run and legacy-result refusal under the workspace lock; `--allow-prior-runs` marks the run not blind permanently; documented as protection against accident (D-04) |
| T-106.1-56 | Tampering | run folder inside the data | mitigate | overlap check refuses; fingerprint unchanged test (REC-05) |
| T-106.1-57 | Spoofing | session bound to another dataset | mitigate | fingerprint comparison on reuse; refusal names the bound run |
| T-106.1-58 | Denial of service | orphaned export child | mitigate | single child via Popen with start_new_session, exits by itself, stdin closed, log to file; tests wait/kill and check pgrep |
| T-106.1-59 | Information disclosure | confidential runs with web tools | mitigate | open-session path records web_tools unknown and warns; the launcher (Plan 17) disables web tools |
| T-106.1-60 | Repudiation | manifest edited by hand | mitigate | `verify` compares manifest.json with fold(log) and artefact hashes with their events |
</threat_model>
