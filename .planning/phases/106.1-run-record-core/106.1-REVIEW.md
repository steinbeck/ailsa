# Phase 106.1: Code Review Report

## Narrative Findings (AI reviewer)

## Summary

I reviewed the run-record package (`src/ailsa/record/`), the tool hooks into `pick`, `lsd`,
`identify`, `nus`, `jcamp`, the spectra export, the launcher, the Claude Code hook entry and the
two example-data scripts. Four findings were confirmed by running code: a planted `json.py` in
the hook's working folder gets executed, `read_experiment` reports fully sampled data as NUS 25 %
on the repo's own test data, `fold` crashes on a `spectra.scanned` event with an integer
`experiments`, and the log reader marks nothing suspect after a duplicated line.

The main problems:

1. The hook (and the spectra export child) start with `python -m`. That puts the working
   folder at the front of `sys.path`, so any `json.py` or `hashlib.py` in a project folder runs
   on every hook event once the hooks are installed globally.
2. Solver output left over from an earlier solve is copied into the next iteration and passed
   off as that iteration's result. `finalize` does not compare the ranking's `.sol` hash with the
   recorded solver output, and its input-hash staleness check can never fire, so a ranking built
   on another solve's solutions is accepted.
3. NUS detection relies on `NusAMOUNT`, which TopSpin writes for every experiment.
4. An explicit `--run` silently falls back to the active run. `ailsa run close --run <typo>`
   therefore closes the wrong run, and closing cannot be undone.
5. Hooks resolved through the cwd marker write any later Claude Code session into a run, even a
   finished one. Every hook event is stamped `after_finish: true`, and `fold` counts those
   prompts as human messages.
6. In blind mode, `--label` (documented as ignored), `--source` and `--licence` are stored in
   `events.jsonl`. The agent can read that file from `../`.
7. `fold` is not defensive about payload types. One writer already emits the wrong type, and
   that breaks status, render, close and finalize.

The append-only log itself holds up under the lock. Exec-form hook settings, alias validation and
remote quoting (`shlex.quote`, `--`, strict scratch regex) are sound.

## Critical Issues

### CR-01: The hook and the view-export child import modules from the working folder (`python -m` puts the cwd on `sys.path`)

**File:** `src/ailsa/record/hooksettings.py:42-45`, `src/ailsa/record/runinit.py:240-251`
**Issue:** `handler()` produces `{"command": python_exe, "args": ["-m", "ailsa.record.hook"]}`.
With `-m`, Python puts the current folder first on `sys.path`, and Claude Code runs hooks in the
session's folder. `ailsa run hooks install` merges the hooks into `~/.claude/settings.json` by
default, so this runs in every session on the machine. In a launched run it runs in the agent's
work folder. A `json.py`, `hashlib.py`, `datetime.py`, `pathlib.py` or `typing.py` in that folder
gets imported instead of the stdlib module. Verified: a `json.py` that writes to stderr, placed
in the folder, ran on `echo '{}' | python -m ailsa.record.hook`. The hook exits 0, so nothing is
noticed while recording silently stops. This is code execution from any cloned repository that
holds such a file. `_start_views` (`sys.executable -m ailsa.cli ...`, which inherits the agent's
cwd) has the same flaw.
**Fix:**
```python
# hooksettings.py
out = {"type": "command", "command": python_exe, "args": ["-I", "-m", MODULE]}
# runinit._start_views
[sys.executable, "-I", "-m", "ailsa.cli", "spectra", "export", ...]
```
(`-I` = isolated mode: no cwd or script folder on `sys.path`, no `PYTHON*` variables, no user
site. Venv site-packages and editable installs keep working.) Add a test that plants `json.py` in
the cwd and asserts the hook still records.

### CR-02: Stale solver output is recorded as the new iteration's result, and `finalize` accepts rankings built from it

**File:** `src/ailsa/record/lsdrec.py:256-271`, `src/ailsa/lsd/runner.py:374-376`, `src/ailsa/record/remote.py:280-296,318-327,513-528`, `src/ailsa/record/rankrec.py:384-389`, `src/ailsa/record/finalize.py:117-136`
**Issue:** `finish_solver_run` copies `out/<stem>.sol`, `out/solutions.smi` and `solncounter`
from the output folder whenever they exist, whatever the outcome. The local runner deletes only
`solncounter` before a solve, and the remote path deletes nothing locally. So if the agent
re-solves in the same folder and the new solve fails (LSD input error, no solution, timeout, MAXT
stop, outlsd failure), the previous solve's `solutions.smi` (and on an input error its `.sol`)
lands in `iterations/itNN/`. It is then registered, `smiles_absent_reason` is set to `None`, and
`solutions.converted` says "converted". On the remote path, `_count_text` falls back to the
stale local `solncounter`, so a `no_solution` iteration can be recorded with a count from the
earlier run. Downstream:
- `_iteration_by_smiles_sha` picks the last iteration with that sha, so a nearest-line ranking of
  it01's solutions is attributed to it02.
- In assigned mode, `rank` on the edited `compound.lsd` reads the stale `.sol`. The recorded
  copy is identical, so `SOL_DIFFERS` does not even trigger. Even when it does trigger it is
  only a warning: `check_ranking` never compares the ranking input's `sol_sha256` with the
  iteration's `solver.json` `files.sol.sha256`.
- `check_ranking`'s "later `lsd.input.registered` with a different sha" test cannot fire,
  because an iteration id is registered exactly once. The input-hash staleness protection is
  dead code.
**Fix:** Before each solve (local in `_execute_lsd`, remote in `solve_remote` before
`_extract_outputs`), remove `{stem}.sol`, `solutions.smi`, `solncounter`, `lsd.out` and
`lsd.err` from the output folder, or solve in a fresh per-iteration folder. In
`finish_solver_run`, copy `solutions.smi` only when this run produced it (keep its mtime or sha
from before the solve). In `check_ranking`, refuse when an input's `sol_sha256` (assigned) or
`smiles_sha256` (nearest-line) differs from the iteration's recorded `solver.json` file hash, and
refuse when the iteration's `solver.finished` outcome is not `solutions`/`limit_reached`.

### CR-03: NUS detection is wrong for practically every TopSpin dataset (fully sampled data reported as NUS 25 %)

**File:** `src/ailsa/case/scan.py:189-191`, `src/ailsa/record/inventory.py:71-75`, `src/ailsa/spectra/export.py:239-243`
**Issue:** `nus_fraction = NusAMOUNT/100 if NusAMOUNT > 0`. TopSpin writes `##$NusAMOUNT= 25`
even when NUS is off (`##$FnTYPE= 0`). Verified on `data/PSP/1`, `6` and `7` (zg30, HSQC, HMBC,
all `FnTYPE 0`): `read_experiment` returns `nus_fraction=0.25`, even for the 1D 1H. Effects:
- every inventory records `nus: {fraction: 0.25}` for fully sampled spectra (REC-28 record is
  wrong);
- `spectra export` skips every raw-only experiment as "NUS data not reconstructed", so the
  rawproc view path is effectively dead;
- `ailsa case scan --format json` (an existing command, used outside any run) now prints
  `nus_fraction: 0.25` for every experiment.
**Fix:**
```python
fntype = _param(text, "FnTYPE")
nus_on = (fntype is not None and fntype.strip() == "2") or (path / "nuslist").is_file()
nus_fraction = (nus_pct / 100.0) if nus_on and nus_pct else None
nus_schedule = (path / "nuslist").is_file() if nus_on else None
```
Add a regression test on `data/PSP/6`.

### CR-04: An explicit `--run` silently falls back to the active run (an irreversible `close` can hit the wrong run)

**File:** `src/ailsa/record/resolve.py:82-85`, `src/ailsa/cli/run.py:191-199,421,569-571`, `src/ailsa/cli/peaks.py:32`, `src/ailsa/cli/spectra.py:95`
**Issue:** `find_active_run(explicit)` tries the explicit id or path first, and if it does not
resolve it carries on to `AILSA_RUN_DIR`, the session pointer and the cwd marker. `_resolve_run`
raises "run not found" only when *nothing* resolves. So `ailsa run close --run <typo>`, run from
inside a run folder or a launched session, closes the active run with exit 0. "A closed run
takes no more material", so the remaining tool calls of that run go unrecorded. `finalize`,
`note`, `status`, `render`, `verify`, `peaks decide`, `model import` and `spectra export --run`
also act on a run other than the one named.
**Fix:**
```python
def find_active_run(explicit=None, *, ...):
    if explicit:
        return _ref(find_run(workspace_root(create=False), explicit), "flag")  # no fallback
    ...
```

### CR-05: Hooks write unrelated later sessions into runs, finished ones included, and change their classification

**File:** `src/ailsa/record/hook.py:281-322`, `src/ailsa/record/log.py:123,206`, `src/ailsa/record/fold.py:209-215,358-361,376`
**Issue:** The hook resolves the run through the cwd marker for *any* session and appends with
`after_finish=True` unconditionally. Hook types are allowed after `run.finished`. With the hooks
installed globally (needed for the in-session path), opening Claude Code anywhere inside a run
folder, for example to inspect a finished run, does all of this to that run:
- appends every prompt (`prompt.submitted`, up to 4000 characters of text) to its log;
- copies that session's transcript into `transcript/` at SessionEnd;
- rewrites `heartbeat.json`.

`fold` counts these prompts as human messages, so a closed run that was `assisted: false`
becomes `assisted: null`, and its benchmark classification changes after the fact. The
`after_finish` flag cannot tell these events apart: every hook event during a run is stamped
`after_finish: true`, contrary to the documented meaning ("true only for hook events written
after run.finished", `events.py:20`).
**Fix:** (1) In `LockedLog.append`, stamp `after_finish = self.finished()` and keep the caller's
flag only as permission (`allow_after_finish`). (2) For a finished run, accept hook events only
from a session bound to that run (`session_id` matches a `run.bound` event or the launcher's
session id); never through the cwd marker alone. (3) In `fold`, ignore events with
`after_finish: true` for `human_messages`, `assisted`, `hook_counts` and `end_ev`.

### CR-06: Blind runs keep `--label` (documented as ignored), `--source` and `--licence` where the agent can read them

**File:** `src/ailsa/record/runinit.py:337,361-373,386`, `src/ailsa/cli/run.py:67,114`, `src/ailsa/record/launcher.py:171`
**Issue:** In blind mode the folder label ignores `--label` (line 337), but `request.args` stores
the raw `sys.argv[1:40]`, label included, in `run.created`. `dataset.source` and
`dataset.licence` are stored verbatim (for example "BMRB bmse000667 (alpha-terpineol)"). The
agent works in `<run>/agent/`, so `../events.jsonl` and `../manifest.json` are one `cat` away. A
benchmark script that passes `--label` to every run (the help text says it is ignored in blind
mode) puts the compound name into each blind agent's reach.
**Fix:** In blind mode, drop `--label`, `--source`, `--licence` and `--prompt` and their values
from `args`; store `source`/`licence` only as `"withheld (blind)"`, or move them into a sidecar
outside the run folder that is merged into the manifest only after `run.finished`. Add a test
that greps `events.jsonl` of a blind run for the label.

### CR-07: `fold` crashes on unexpected payload types; one writer already emits one (status, render, close and finalize then fail)

**File:** `src/ailsa/cli/spectra.py:43-46`, `src/ailsa/record/fold.py:100-107,398-400`
**Issue:** `runinit` writes `spectra.scanned` with `experiments` as a list of dicts.
`cli/spectra.py::_inventory_for_run` writes the same event type with
`experiments: len(...)` (an int). `_h_scan` does `for item in payload.get("experiments") or []`,
and with any non-zero count that raises `TypeError: 'int' object is not iterable` (verified).
After that `rebuild_manifest`, `render_run`, `ailsa run status`, `close_run` (and so the
launcher's close) and `finalize_run` (after the declaration is written) all raise. The path
fires when init's inventory step failed and `spectra export` then builds the inventory. More
generally, `fold` assumes types everywhere (`max()` over `utc` values of mixed type, iteration
over list fields). D-09 requires readers to show a changed record, not crash on it.
**Fix:** Write the list form in `cli/spectra.py` (same payload as `runinit`). In `fold`, guard
each handler (`items = p.get("experiments"); if not isinstance(items, list): items = []`), wrap
handler calls in `try/except (TypeError, ValueError, AttributeError)` that records a manifest
warning, and coerce `utc` values to `str` before `max()`.

## Warnings

### WR-01: The log writer reuses sequence numbers after a stray line, and the reader marks suspects by seq instead of by position

**File:** `src/ailsa/record/log.py:62-85,354-358`
**Issue:** `_tail_state` takes `seq` from the last *parseable* line, not the highest one. After a
duplicated or out-of-order line the writer appends events with seq numbers that already exist.
The reader then sets `first_bad_seq = expected_seq` and marks only events with
`seq >= first_bad_seq` as suspect. Verified: three events, a duplicate of line 2, then one
`append_event` gives `first_bad_seq=4` while no event has seq 4. The duplicate and the new
"seq 3" event render as clean rows and the break marker never appears (D-09). On a window full of
unparseable lines, `_tail_state` falls back to seq 0 with the genesis hash and restarts the chain.
**Fix:** Mark suspects by file position (index of the first bad line), not by seq. In
`_tail_state`, return `max(seq)` over the parseable tail and refuse (or emit `log.recovered`)
when the last line's seq is not the maximum. Never fall back to genesis when `size > 0`.

### WR-02: Short `os.write` is not checked in the append path

**File:** `src/ailsa/record/log.py:144,161`
**Issue:** `os.write` may write fewer bytes (ENOSPC, network or FUSE filesystems). The event is
returned as appended and, for `run.finished`, `finished.json` records the head hash of a line
that is not on disk.
**Fix:** Loop until all bytes are written, or raise. Write `finished.json` only after a
full-length write and fsync.

### WR-03: Symlink defences are inconsistent: several writers follow symlinked folders inside the run

**File:** `src/ailsa/record/rankrec.py:326-338,570-582`, `src/ailsa/record/tooldata.py:131-143,196-208,223-231`, `src/ailsa/cli/peaks.py:172-184`, `src/ailsa/cli/model.py:110-123`, `src/ailsa/record/lsdrec.py:212-218`, `src/ailsa/record/transcript.py:98-106`, `src/ailsa/record/remote.py:296,455-457`
**Issue:** `register_artefact`/`copy_into_run` go through `safe_relpath`, which refuses
symlinked components. These writers do not:
- `_write_new` callers (rankings, analyses, picks, identity, peak decisions, atom models,
  `lsd.out`/`lsd.err`);
- `run_output_dir`;
- the transcript copy;
- remote `_extract_outputs` and the `ring3`/`ring4` writes.

They check only `lexists(target)` and then `mkdir(parents=True, exist_ok=True)` into whatever
`rankings/`, `peaks/`, `transcript/` or `nus/` points to. The agent can write to the run folder.
A symlinked `transcript/` or `nus/` sends transcripts or NUS stages into the dataset (REC-05) or
anywhere else.
**Fix:** Route every run-folder write through
`safe_relpath(run_dir, rel)` before `mkdir`/write (and in `run_output_dir`). In the transcript
copy and `_extract_outputs`, refuse when `target.parent` or any component is a symlink.

### WR-04: Process hygiene: remote solves, the launcher and the export child can leave orphans or open runs

**File:** `src/ailsa/record/remote.py:448-510`, `src/ailsa/record/launcher.py:190-195,223-252,318-351`, `src/ailsa/record/runinit.py:235-259`
**Issue:**
- `solve_remote` cleans the remote scratch only on `ValueError` from staging and on handled
  failures. `KeyboardInterrupt`, `SIGTERM` (for example a Bash-tool timeout) or an `OSError`
  after `probe_remote` leave LSD running remotely. Without `timeout` on the host it runs with no
  limit, and the scratch folder stays.
- In interactive mode the launcher's time limit sends `SIGTERM` to `claude` only (no process
  group), so its Bash-tool children (LSD, scripts) are orphaned.
- `KeyboardInterrupt` in `_wait_with_limit` propagates out of `launch()` before
  `run.attempt.ended`/`close_run`, which contradicts "never leaves an open run".
- `close_run` raising `CloseRefused` (the agent ran `ailsa run close`), or an `OSError` from
  `copytree` after `init_run`, aborts with a traceback and leaves no rendering, or an unclosed
  run.
- The detached `spectra export` child can outlive the run. It then writes view files into a
  finished run, its registration is refused, and the files stay unregistered.
**Fix:** Wrap the remote poll in `try/finally` that runs `_kill_script` + `_cleanup` on any
`BaseException`. Start the interactive harness with `start_new_session=True` too, and forward
SIGINT/SIGTERM. Put `run.attempt.ended` + close + render in a `finally` and catch
`CloseRefused`. Have `close_run` wait briefly for (or terminate) the recorded `views_pid`, and
have the export child check `finished.json` before writing.

### WR-05: Remote tar streams break when the login shell prints anything to stdout

**File:** `src/ailsa/record/remote.py:78,513-530`
**Issue:** Every remote step runs as `bash -lc`. Any stdout from `~/.bash_profile` or `~/.profile`
(conda or module banners, `echo`s) is prepended to the fetched tar stream. `_extract_outputs`
then fails and the solve is recorded as `error` ("fetch of solver outputs failed"), even though
LSD succeeded. The probe tolerates the noise; the fetch does not.
**Fix:** Emit a unique sentinel line before `tar cf -` and strip everything up to it, or
base64-encode the tar between markers. Alternatively run the fetch with `bash -c` and an explicit
`PATH` taken from the probe.

### WR-06: Behaviour outside a run changed for `ailsa lsd run` (D-07 "outside any run tools behave as today")

**File:** `src/ailsa/cli/lsd.py:290-320`, `src/ailsa/lsd/runner.py:424-449`
**Issue:** The JSON output gains `outcome`, `partial_count` and `elapsed_s` unconditionally.
Text output for a timeout changes from "LSD failed (return code: -1) ..." to "LSD stopped at the
time limit ...". A MAXT time stop now returns early with `success: false` and **without running
outlsd**: before, the partial `.sol` was converted to `solutions.smi`. The unchanged frontier
skill (D-01) loses the SMILES for time-limited solves and sees a different `success`.
**Fix:** Add the new JSON keys and the timeout wording only when a run is active (as
`_echo_outcome` already does). Keep the outlsd conversion of partial `.sol` files on a time stop
and record `outcome=timeout` alongside.

### WR-07: Tool-written NUS and JCAMP outputs inside the run are never registered and get flagged as "unverified"

**File:** `src/ailsa/cli/nus.py:604-612`, `src/ailsa/nus/runner.py:422-428`, `src/ailsa/cli/jcamp.py:332-343`, `src/ailsa/record/finalize.py:144-165`
**Issue:** REC-05 redirects NUS stages, NUS peak lists and JCAMP outputs into `<run>/nus`,
`<run>/peaks/nus/...` and `<run>/jcamp/...`, but no event registers those files. `finalize`
and `run verify` report each one as "unverified file outside the working folder" (D-08 is meant
for agent files), which fills the manifest with false warnings.
**Fix:** Register the written files (`register_existing` with kinds `nus-stage`, `nus-peaks`,
`jcamp-peaks`) at the end of each command, or add those trees to a tool-owned allow list that
`unregistered_files` and `_scan_unregistered` share.

### WR-08: Experiment ids in pick and NUS records bypass the inventory's aliases

**File:** `src/ailsa/record/tooldata.py:31-39,105-110`, `src/ailsa/record/inventory.py:126-144`
**Issue:** The inventory replaces non-numeric experiment folder names with `x1`/`u1` ("so a
blind run records nothing that could name the compound"). `record_pick` uses the raw folder name
(`experiment_of(path)`) for `exp:`, `pick:` and `pk:` ids and for the path
`peaks/<folder>.<n>.json`. Picks therefore never link to inventory experiments: `fold` creates
separate `exp:` keys. Blind aliasing is bypassed. Names with spaces or `:` break the `ID_PATTERNS`.
**Fix:** Resolve the experiment label from the run's registered inventory (map folder to label
with the same sort rule) and use that label in ids and paths. Reject or alias folder names that
do not match `[^:\s]+`.

### WR-09: A Claude Code run without hooks is reported as "hooks recorded"

**File:** `src/ailsa/record/transcript.py:181`, `src/ailsa/record/fold.py:358-359,374`
**Issue:** `record_transcript_models` appends `agent.model_reported` with actor kind `"hook"`.
`finalize` calls it in every Claude Code session (the session id comes from the environment), so
`fold` sets `hooks_recorded = True` even when no hook ever ran. The rendering then prints "Hooks:
prompts 0, permission waits 0, ..." instead of "not recorded by this harness" (D-13), and zero
counts read as "nothing happened".
**Fix:** Use `{"kind": "tool", "name": "transcript"}` in `record_transcript_models`. Derive
`hooks_recorded` from hook-only event types (`session.started`, `tool.shell`,
`prompt.submitted`, ...) rather than from actor kind.

### WR-10: Run state and verification are wrong after mid-run session ends and post-finish hook events

**File:** `src/ailsa/record/fold.py:362-363,409-417`, `src/ailsa/record/hook.py:289`, `src/ailsa/cli/run.py:269-283`
**Issue:** `end_ev` is set by any `session.ended` or `run.attempt.ended` and never reset. After a
`/clear` (SessionEnd, reason `clear`, then a rebound session) the run keeps working but is shown
as "stopped before a result (inferred)". Separately, hooks rewrite `heartbeat.json` and append
`after_finish` events after close. `manifest.json` then differs from a fresh fold, and
`ailsa run verify` fails (exit 1) on an intact run, because clock keys are ignored only for live
states.
**Fix:** Treat an end event as final only if no non-hook run activity follows it (or only
`run.finished`/the last `run.attempt.ended`). In `verify`, ignore `after_finish` events and
`heartbeat_utc` for finished runs, or have the hook skip the heartbeat when `finished.json`
exists.

### WR-11: The recorded LSD binary identity is not taken from the binary that actually ran

**File:** `src/ailsa/cli/lsd.py:104-110`, `src/ailsa/record/env.py:70-71`, `src/ailsa/lsd/runner.py:590`
**Issue:** `_finish_record` records `probe_lsd()`, which looks for `LSD` and then `lsd` on
`PATH`. The runner executes `self.lsd_path` from `_find_lsd()` (`which lsd`, then
`SEARCH_PATHS`). On a case-sensitive host with both binaries, or with a `SEARCH_PATHS` fallback,
the recorded version and sha256 (REC-31) describe a different binary.
**Fix:** Pass the runner's `lsd_path`/`outlsd_path` to `probe_binary` (add a `path=` argument)
and record exactly that.

### WR-12: The counters live outside the hash chain; a missing or corrupt file silently resets ids

**File:** `src/ailsa/record/log.py:96-107`
**Issue:** `.counters.json` that is unreadable or invalid becomes `{}` without a warning. Ids then
restart: `it01`, `rk01`, `art:*:1`. Every later `copy_into_run` or ranking write fails with
`FileExistsError` (that record step is lost), and kinds with fresh paths get duplicate artefact
ids, which `artefact_index` silently overwrites. The manifest is supposed to be a pure function
of the log, yet ids depend on an unchained side file.
**Fix:** On a missing or invalid counter file, rebuild the counters from the log (max id per kind
in `read_events`) and raise a `warning.raised`. Alternatively derive ids from the log under the
lock.

### WR-13: `env.captured` records the real hostname and absolute home paths

**File:** `src/ailsa/record/env.py:67,152,261-266`, `src/ailsa/record/runinit.py:362`
**Issue:** `remote.py` promises "only the host alias is ever used or recorded", and
`workspace.host_alias()` exists for that purpose. But `probe_environment` stores
`socket.gethostname()` and the absolute paths of LSD, outlsd and the database, and `run.created`
stores the absolute dataset path, all with user names. Records of class `public` are meant to be
shared.
**Fix:** Record `host_alias()` and paths relative to `~` (or basenames plus sha256). Keep the
absolute dataset path out of public-class records.

### WR-14: The blind inventory keeps JCAMP name headers and file names

**File:** `src/ailsa/record/inventory.py:18-19,79-113`
**Issue:** `_DROP_HEADERS = {"TITLE", "OWNER"}` keeps `##NAMES=`, `##CAS NAME=`,
`##CAS REGISTRY NO=`, `##$NAME=`, `##SAMPLE DESCRIPTION=` and `##BLOCK_ID`. JCAMP file names are
stored verbatim. That contradicts the module contract ("a blind run records nothing that could
name the compound").
**Fix:** Allow-list the headers that are safe (nucleus, frequency, sweep width, units, data type,
solvent) instead of deny-listing two. In blind mode, alias the JCAMP file paths like the folder
names.

### WR-15: The "imported" provenance is dropped in the manifest and the rendering

**File:** `src/ailsa/record/fold.py:148-157`, `src/ailsa/record/render.py:211-212`
**Issue:** `ailsa lsd import` can register any `.sol`/`solutions.smi` an agent produced, labelled
`provenance: imported` in `solver.finished`. `fold` keeps only outcome and count, and
`final_results.md` lists "Iterations covered" without provenance. A declaration based on
hand-imported solver output therefore looks the same as one based on a real solve.
**Fix:** Keep `provenance`, `host` and `remote` in the manifest's iteration entries, and mark
imported iterations in `render_final` ("imported, not run by ailsa").

### WR-16: `ailsa run hooks install/uninstall` replaces a symlinked `settings.json` and rewrites the whole file

**File:** `src/ailsa/record/hooksettings.py:139-141,152-153`, `src/ailsa/record/fsutil.py:14-28`
**Issue:** `atomic_write_json` replaces the file through `os.replace`. A dotfile-managed
`~/.claude/settings.json` symlink becomes a regular file and the link to the managed copy is lost.
`sort_keys=True` also reorders and reformats the user's whole settings.
**Fix:** Resolve the symlink and write the target (`path = path.resolve()`). Preserve key order
(`sort_keys=False`) and indentation.

## Info

### IN-01: Tool recording relies on a private Click attribute

**File:** `src/ailsa/record/toolrec.py:78-80`
**Issue:** `_pending_argv` reads `ctx._protected_args` (Click ≥ 8.2 internals). If a Click release
renames it, `tool.invoked` recording silently stops.
**Fix:** Record from `sys.argv[1:]` in `invoke_recorded`, or pin the attribute in a test.

### IN-02: `_actor_name` takes option values as command words

**File:** `src/ailsa/record/toolrec.py:102-104`
**Issue:** For `ailsa pick --format json 1d x`, the actor name becomes "ailsa pick json".
**Fix:** Use `ctx.invoked_subcommand` or the resolved command path.

### IN-03: The unregistered-file scan and its constants are duplicated

**File:** `src/ailsa/cli/run.py:21-35,245-263`, `src/ailsa/record/finalize.py:38-52,144-165`
**Issue:** `_RECORD_FILES`, `_KNOWN_PATHS`, `_FREE_DIRS` and the walk exist twice and can drift.
**Fix:** Have `verify` call `finalize.unregistered_files`.

### IN-04: `--time-limit` is not validated

**File:** `src/ailsa/cli/run.py:469`, `src/ailsa/record/launcher.py:238`
**Issue:** 0 or a negative value makes `proc.wait(timeout=...)` expire at once, so the harness is
killed immediately.
**Fix:** `type=click.IntRange(min=1)`.

### IN-05: Readers never take the log lock

**File:** `src/ailsa/record/log.py:263-276`, `src/ailsa/record/closing.py:32-41`
**Issue:** A reader racing an `os.write` (async PostToolUse hooks) reports a transient
"truncated" break. `close_run` computes the permanent `run.finished.state` from an unlocked read.
**Fix:** Take a shared lock (`LOCK_SH`) in `read_events`, or ignore an unterminated tail while the
lock is held by a writer.

### IN-06: The config is re-read for every event

**File:** `src/ailsa/record/workspace.py:46-57,89-92`
**Issue:** `host_alias()` calls `load_config()` on every envelope, and an invalid config prints
its warning once per event.
**Fix:** Cache the config per process (`functools.lru_cache`).

### IN-07: The SQLite URI is not percent-encoded

**File:** `src/ailsa/record/env.py:154`
**Issue:** A database path containing `?`, `#` or `%` breaks `file:{path}?mode=ro`.
**Fix:** `f"file:{urllib.parse.quote(str(path))}?mode=ro"`.

### IN-08: View-export mapping and concurrency are fragile

**File:** `src/ailsa/spectra/export.py:249-253,383-395`, `src/ailsa/cli/spectra.py:111-122`
**Issue:** Inventory labels are mapped to folders by list position. If the folder set changed
since the inventory was written, the wrong folder is exported under a label. The background
export and an agent-run export can write the same targets at the same time (check-then-write on
`view.json`), which gives duplicate registrations and sha mismatches.
**Fix:** Store a private label-to-folder mapping. Take a per-experiment lock (`O_EXCL` marker)
before exporting.

### IN-09: The download digest is keyed on file names only

**File:** `scripts/example-terpineol/download_bmrb.py:84`
**Issue:** `target.name` (`fid`, `acqus`, repeated across experiments) makes the printed digest
order-dependent and ambiguous.
**Fix:** Use the path relative to `raw/`.

### IN-10: Context files with the same basename overwrite each other

**File:** `src/ailsa/record/launcher.py:191-195`
**Issue:** The second copy silently replaces the first, while both sha256 values are recorded.
**Fix:** Refuse duplicate basenames in `_context_entries`.

### IN-11: `--alternative` is accepted without a ranking

**File:** `src/ailsa/record/finalize.py:178,307`
**Issue:** With no ranking, `top` is `None`, so any rank ≥ 1 is accepted for outcomes such as
`no_structure_fits`.
**Fix:** Refuse `--alternative` when there is no ranking.

### IN-12: Two smaller inconsistencies (resolver fallback and remote conversion on timeout)

**File:** `src/ailsa/record/resolve.py:86-106`, `src/ailsa/record/remote.py:247-254`
**Issue:**
- When `AILSA_RUN_DIR` does not resolve but a cwd marker does, the tool records into the cwd run
  without any warning.
- The remote `run.sh` converts a partial `.sol` after `timeout` kills LSD, while the local runner
  skips conversion on a time stop. The same input gives different SMILES availability locally and
  remotely.
**Fix:** Warn when `AILSA_RUN_DIR` is set but unresolved, even if another source resolves. Align
the two conversion policies (see WR-06).
