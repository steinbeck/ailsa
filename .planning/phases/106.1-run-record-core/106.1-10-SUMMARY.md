# Phase 106.1 Plan 10: Spectra view products Summary

`ailsa spectra export` writes noise-normalised, log-quantised int16 2D levels with signed max-abs pooling, float32 1D data and skyline projections, and registers them in the run.

## Tasks

1. Quantisation, pooling and per-experiment export (commit d371196).
2. `ailsa spectra export` command with run registration (commit bf5bf88).

## Measurement (processed alpha-terpineol example, 7 experiments, dev host)

- Total 2.4 s, 12.16 MB written (12162424 bytes).
- Largest single experiment 1.67 s (experiment 1, includes the first-import cost of nmrglue/scipy); the others 0.01-0.29 s.
- Well under 20 s, so the inline export at `run init` is fine; Plan 14 may still run it detached.

## Verification

- `tests/record/test_spectra_export.py`: 21 passed, 1 skipped without the env var; the optional real-data test passed with `AILSA_EXAMPLE_TERPINEOL` set (60 s alarm).
- A one-pixel cross-peak (negative, in noise) survives all levels and dequantises within 2 %; round-trip error under 1 % for |z| >= 1.
- Dataset fingerprint identical before and after the export (REC-05). No multiprocessing in the module.
- ruff clean; mypy clean for the new files (pre-existing errors in `lsd/runner.py` are out of scope).

## Deviations from Plan

- Registration of the files of one experiment uses `log_session` directly (`register_result`) so that one `spectrum.processed` event carries all artefacts; `register_existing` would write one event per file.
- Skipped/failed events carry a state guess (vendor if the inventory says processed, else rawproc) because the payload state is typed to the processing-state vocabulary.
- Synthetic test data needs a small `fid`/`ser` because the existing reader also reads parameters through the raw file; unchanged reader behaviour.
