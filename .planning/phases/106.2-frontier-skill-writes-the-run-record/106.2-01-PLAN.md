<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent -> record (notes, self-reported model) | an agent's claim about its name and model enters the record as untrusted text |
| Claude Code hook payload -> record | harness JSON (tool_input, response) crosses into the event log |
| installed skill under ~/.claude -> environment record | files outside the package are hashed and compared |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106.2-01 | Spoofing | fold `_h_model_reported` (self-report sender) | mitigate | self-reports never override harness/transcript in the headline (`SOURCE_PRECEDENCE`); every report keeps its `source`, so a false claim stays visible as self-report |
| T-106.2-02 | Tampering | render diary line for model reports | mitigate | every agent-supplied field goes through `md_escape`; test covers a field with Markdown special characters |
| T-106.2-03 | Repudiation | manifest rebuild | mitigate | additive payload keys only; byte-stable rebuild test keeps old records verifiable |
| T-106.2-04 | Information disclosure | `command_skill_files` | accept | records only relative names and hashes of the user's own skill files, never content or absolute home paths |
| T-106.2-05 | Information disclosure | test fixtures in the public repo | mitigate | synthetic ids and placeholder model names; no prompts or paths from real runs |
| T-106.2-SC | Tampering | package installs | accept | no package is installed or added in this plan |
</threat_model>
