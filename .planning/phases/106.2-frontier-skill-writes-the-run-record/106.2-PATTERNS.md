## Pattern Assignments

### `src/ailsa/skills/ailsa/commands/case.md` (skill command, event-driven)

**Analog:** `src/ailsa/skills/ailsa-lite/SKILL.md` (lean skill 0.3.0). The coordinator copies the wiring, not the
prose style (case.md is a team coordinator, SKILL.md a single agent).

**First step: init after the prerequisite checks** (SKILL.md lines 38-48):
```bash
ailsa --version
ailsa lsd check                                   # LSD and outlsd must be available
ailsa predict c13 "CCO" --format json | head -3   # the prediction database must work
ailsa run init DATASET                            # first step: creates the run record
```
`ailsa run init` prints `RUN:` and `WORK:`. `cd` into the WORK folder and keep every file there;
if a run is already active it prints the same folder.

Frontier shape (RESEARCH "Code Examples"): `ailsa run init <compound_path> --formula <formula> --skill ailsa --mode team`,
then `ailsa run note "start: ..." --phase peak-picking --sender coordinator`. `WORK` becomes `{work_dir}` in every
spawn prompt and `[BEGIN]` message, as an absolute path. Idempotent re-init is the recovery after compaction.

**Result: declared once, with an explicit ranking id** (lean SKILL.md lines 121-139 and `references/ranking.md:158-162` use
`finalize --outcome proposal --ranking latest ...`). Do NOT copy `--ranking latest`; the frontier analyst makes a
nearest-line cross-check after the decisive ranking, which would be `latest` (`finalize.py:73-78`). Use:
```bash
ailsa run finalize --outcome proposal --ranking rk02 --candidate 1 --confidence medium \
  --caveat "..." --open-question "..." --next-step "..."
ailsa run render
```

**Edits to apply (current line numbers in case.md):**
- 19-25, 38: objective and `## Contents` (test_toc: entries must match headings or `<step name>`).
- 142-220: add `{work_dir}` to every `Task(... prompt=...)`; analyst no longer writes `final_results.md`.
- 258-305: delete (`run_start` stamp, `analysis/.run_manifest.json`, web-view launch, `**Dashboard:**`). Current text to remove:
  ```
  **First, stamp timing** (the timing step ...): take the `run_start` stamp (this one also runs `mkdir -p <compound_path>/analysis`) ...
  **Write the run manifest** ... cat > "<compound_path>/analysis/.run_manifest.json" <<JSON
  ```
- 320-357: `write_progress` becomes notes; delete the `timing` step.
- 455-490 (`terminate_team`): replace "The web-view server stays running" paragraph and "Step 0: Finalize timing" with
  `ailsa run finalize` (or `ailsa run close --reason "..."` on every failure path) plus `ailsa run render`.
  Outcome table for every exit path: RESEARCH "Pattern 2".

**Guard constraints** (`tests/test_skill_frontier.py`): file under 500 lines; no phase numbers, dates, requirement IDs such as `REC-25`,
`D-NN`, `CASE\d+`, model IDs, "orchestrator", "team lead", capital-letter emphasis, `lucy`; file tokens in prose limited to packaged files
plus `RUN_ARTEFACTS = {"CASE-PROGRESS.md", "final_results.md", "DIAGNOSTIC-REPORT.md"}` (line 35).

## Shared Patterns

### One writer per artefact: agents decide, tools write
**Source:** `src/ailsa/skills/ailsa-lite/SKILL.md` lines 38-48, 118-139; `docs/RUN-RECORD.md`.
**Apply to:** every skill text edit. A skill never writes a file for which the record has a command: progress is `ailsa run note`, the result is
