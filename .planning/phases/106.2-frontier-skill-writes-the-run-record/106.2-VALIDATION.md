> Per-phase validation contract for feedback sampling during execution.
> Source: `106.2-RESEARCH.md` § Validation Architecture. The per-task map is filled once the plans exist.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest (`pyproject.toml` `[tool.pytest.ini_options]`, `testpaths = ["tests"]`), ruff, mypy strict; Click `CliRunner`; fake `claude` shim as in `tests/record/test_launcher.py` |
| **Config file** | `pyproject.toml` |
| **Quick run command** | `~/.venvs/ailsa/bin/python -m pytest -q tests/test_skill_frontier.py tests/test_skill_lite.py tests/test_skill_files_unchanged.py tests/test_benchmark_scripts.py` (about 10 s on vitus); package tasks add the touched `tests/record/<file>` |
| **Full suite command** | on Sheldon only, in a separate checkout reached by git bundle and fast-forward: `pytest`, `mypy src/ailsa`, `ruff check src tests`, compared with the recorded baseline |
| **Estimated runtime** | quick run about 10 s; wave check about 60 s in two calls; full suite a few minutes on Sheldon (never on vitus or the laptop) |

---

## Sampling Rate

- **After every task commit:** quick run command plus the touched `tests/record/` file; skill-text commits also pass the pre-commit hook (form checks, hash guard, local answer scan)
- **After every plan wave:** `tests/record/test_launcher.py tests/record/test_hook.py tests/record/test_fold.py tests/record/test_render.py` plus the quick run command
- **Before `/gsd-verify-work`:** full suite, mypy, ruff on Sheldon equal to or better than the baseline (the five web-view-extra failures disappear); both proof runs pass `ailsa run verify`; answer-scan output read; owner checkpoint on the team run
- **Max feedback latency:** 10 seconds for the quick run
