### CR-01: Watchdog abort sends SIGTERM to unrelated launcher runs of the same user on the shared host

**Files modified:** `scripts/uat_watchdog.py`, `tests/case-benchmark/blind_case_run.sh`, `tests/test_benchmark_scripts.py`
**Commit:** 36ae0e6
**Applied fix:** the runner starts the launcher in the background, writes its pid to
`<case>/launcher.pid` and waits for it. The abort (`abort_chunk(results_dir)`, script run with the
series' results root) no longer pattern-matches every process of the user. A launcher is signalled
only through its recorded pid, only while that pid still carries the runner's exact launcher
arguments (`ailsa run start … --skill ailsa --headless --blind`), and only when the case has no
`meta.json` yet (an older pid may have been reused). A harness left over after 30 s is killed with
its own process group only when its `--settings` file lies in a run record under this results root.
The KILL patterns over `-p /ailsa:case` and `--resume … --dangerously-skip-permissions` and the
`timeout 3600` steps are gone.
**Test:** `test_watchdog_abort_selects_only_the_runners_runs` (predicates: none of a lean run, an
interactive frontier run, a non-blind headless run, `claude -p hi`, `claude --resume …` with and
without the nudge, the watchdog's own command line, a harness of another workspace or series, or
the abort script itself is selected); `test_watchdog_abort_signals_recorded_launchers_only` (live
processes: only the recorded launcher gets SIGTERM and only this series' harness gets SIGKILL; a
reused pid, a finished case, an interactive run and a foreign harness survive);
`test_runner_records_the_launcher_pid`.

### WR-06: Runner silently runs whichever `claude` comes first on PATH; meta.json still names the pinned binary

**Files modified:** `src/ailsa/record/launcher.py`, `src/ailsa/cli/run.py`, `tests/record/test_launcher.py`, `tests/case-benchmark/blind_case_run.sh`, `tests/test_benchmark_scripts.py`, `docs/RUN-RECORD.md`
**Commit:** 127dff4
**Applied fix:** the reviewer's preferred fix. `ailsa run start --harness-bin PATH` uses the path as
the first argument of the first attempt and of every resume. A path that is not an executable file

`CLAUDE_BIN` once to an absolute path, passes it with `--harness-bin`, writes that path to meta.json
and refuses an unknown binary (reason `claude_bin_not_found`). It no longer changes PATH.
**Test:** `test_harness_bin_runs_exactly_that_file` (any file name, also on resume; recorded
binary and version); `test_default_harness_bin_is_resolved_and_recorded`;
`test_missing_harness_bin_refused_before_the_run`;

### WR-09: Slash-started runs stay open and session-bound after `finalize`; a second `/ailsa:case` reuses the old run

**Commit:** d725ccb
**Applied fix:** terminate_team and the run-record reference close the record right after a
successful `finalize` (`ailsa run close --reason "result declared"`), then render. Before writing
this, the semantics were checked in code. `close_run` keeps the state `result_declared`, because
the fold derives it from the declaration. `init_run` skips a finished session run and creates a new
one. `render_run` works on a closed run. The launcher's `_close_quietly` already accepts a run its
agent has closed. A launcher-started run therefore closes the same way. case.md's "no record is
left open" sentence is true again (case.md now 493 lines).
**Test:** `test_close_after_finalize_keeps_the_result_and_frees_the_session` (record semantics);
`test_terminate_closes_after_finalize` (contract: finalize, then close, then render).
