# Phase 106.2 Plan 03: Launcher starts and resumes the frontier skill Summary

`ailsa run start --skill ailsa` starts `/ailsa:case <dataset> [formula]` with the agent-teams flag, records the installed frontier skill, and with `--resume-attempts N` resumes the same headless session (`claude --resume <sid> -p <nudge>`) inside one record until it declares, closes, is signalled, hits `--deadline` or runs out of attempts.

## Commits

- 8647ab9: feat(106.2-03): launcher starts the frontier skill
- c2894f5: feat(106.2-03): launcher resumes a headless run until it declares a result

## What changed

- Frontier path: refused with exit 2 (before any run folder) when the harness is not Claude Code or `~/.claude/commands/ailsa/case.md` is missing, with the message naming `ailsa skill install ailsa --target claude`. No skill copy into the work folder. The lean default is unchanged and sets no teams flag.
- Resume: `_launch` loops over numbered attempts; attempt k>1 uses `build_resume_argv` with the same extra harness arguments (blind fence). Each attempt's limit is the smaller of `--time-limit` and the remaining deadline. Model report and session binding are written once. Run is always closed (once) and rendered afterwards. Result and text output carry `attempts`.
- Validation: `--resume-attempts` above 1 requires headless Claude Code; below 1 refused; all before run creation.
