<inventory_spec>
Command line (argparse, `main()` guard, follows the layout of other `scripts/*.py`):
- `build [--baseline REV | --old-dir DIR] [--new-dir DIR] [--out DIR]`
- `todo --file OLD_REL_PATH [--out DIR]`
- `check [--files OLD_REL_PATH ...] [--lost-only] [--meaning] [--out DIR]`

Defaults: `--baseline frontier-skill-pre-106`; old files = every `*.md` under
`.claude/commands/lucy-ng/` and `.claude/agents/` at that revision except `supervisor.md` (listed
as excluded in the output header; the agent is removed by the locked decision); `--new-dir
src/ailsa/skills/ailsa` (every `*.md` except `CHANGELOG.md`, recursive); `--out` =
`$AILSA_RULE_INVENTORY_DIR` or `~/Dropbox/develop/data/skill-rule-inventory-106`. With
`--old-dir`, old files are read from a directory instead of git (used by tests). The script exits
2 if `--out` resolves inside `git rev-parse --show-toplevel`.

Segmentation (frontmatter skipped): one unit per list item (`- `, `* `, `1. `), per table row
(separator rows skipped), per sentence of paragraph text that contains a normative word (must,
never, always, do not, only, required, mandatory, binding, critical, stop, before, after, if),
and per fenced code block (kind `code`). Headings are not units.

Normalisation before matching: lowercase; strip markdown emphasis characters and backticks;
apply the rename map (`lucy-ng` -> `ailsa`, `lucy <word>` -> `ailsa <word>`, `lucy-<agent>` ->
`ailsa-<agent>`, `~/.claude/commands/lucy-ng/references/` -> `~/.claude/ailsa/references/`,
`orchestrator` -> `coordinator`, `devils-advocate`/`devils advocate`/`Devils-Advocate` -> `devil's
advocate`, `NMR-Chemist` -> `nmr chemist`, `LSD-Engineer` -> `lsd engineer`, `Solution-Analyst` ->
`solution analyst`); tokens are words of two or more characters minus a stopword list that
includes the emphasis words (must, never, always, mandatory, binding, important, required,
forbidden, critical, only, exactly, verbatim, absolute).

Matching: score = max over new units of max(Jaccard(old, new), 0.95 x containment of old tokens
in the new unit plus its next two units in the same file). Code units match only code units.
Status: `same` (score >= 0.85), `reworded` (0.45 <= score < 0.85), `LOST` (< 0.45). If the old
unit contains a negation (never, not, no, without, do not) and the matched new unit contains none,
the status is at least `reworded` with hint `negation?`. Thresholds are module constants with a
comment.

IDs: `<old file stem>:<first 10 hex of sha1(normalised text)>`, suffix `-2`, `-3` for duplicates
in one file; stable because the old text is fixed by the tag.

Hints (auto-classification for review only): `D01` (unit has a model ID or `MODEL MISMATCH`),
`D03` (unit has `CASE\d+`), `history` (phase number, ISO date, ticket ID, `Bug \d`, `UAT`),
`deadref` (`skill/` path or `SKILL.md`), `emphasis` (unit has an emphasis word in prose).

Files in the output folder (`build` rewrites only `inventory.tsv` and `pairs.tsv`; it never touches the hand-maintained files):
- `inventory.tsv`: id, old_file, old_lines, kind, emphasis (yes/no), hint, new_file, new_lines, score, status
- `pairs.tsv`: id, status, old_text, new_text (private, for review)
- `verdicts.tsv` (edited by hand): id, verdict, note; verdict one of found, dropped-D01, dropped-D03, dropped-history, dropped-deadref, merged-duplicate, restored
- `reasons-<old stem>.tsv` (template from `todo`, filled by hand): id, old_lines, summary, reason_known (yes/no), reason; `todo` never overwrites, it appends ids that are missing
- `meaning.tsv` (edited by hand, Plan 11): id, verdict (same/different), note

`check` prints counts per status and hint, then the unresolved items within the selected old
files (all if `--files` is absent): LOST rows without a verdict; emphasis units without a reasons
entry (skipped with `--lost-only`); with `--meaning`, reworded rows without a `meaning.tsv`
verdict or with verdict `different`. Lines show id, old file:lines, hint, score, never the unit
text. Exit 0 when nothing is unresolved, else 1.
</inventory_spec>
