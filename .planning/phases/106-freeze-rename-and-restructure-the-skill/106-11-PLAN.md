Run the meaning check of the rule inventory: read each reworded rule pair, decide whether the new
text says the same thing as the old (apart from the changes D-01..D-03 allow), fix any rule whose
meaning drifted, and produce the D-06 report.

Purpose: D-06 asks that any rule whose meaning changed beyond D-01..D-03 be reported; the machine
match finds lost rules, a reader finds changed ones. This plan is executed by a fresh executor that
did not write the restructured text, which is the "fresh reviewer instance" of the research.
Output: `meaning.tsv` (private), fixes if any, counts in the CHANGELOG and the SUMMARY.
</objective>

<review_rules>
A pair is `same` when the new text keeps the rule's subject, action, condition and polarity. These
differences are permitted and still `same`: a model ID or model comparison removed (D-01); capital
emphasis replaced by a plain sentence, with or without an added reason sentence (D-02); a dataset
number, compound name or worked story removed while the rule stays (D-03); the old project name,
the old command or agent names, and role terms replaced by the current ones; a numbered
cross-reference replaced by a named one. A pair is `different` when a prohibition became a
preference ("never" to "avoid"), a condition was dropped or added, a threshold or count changed,
an order of steps changed in a way that matters, or the new text covers less than the old.
Rows with hint `negation?` get extra care.
</review_rules>
</context>
