- D-02, rationale instead of emphasis: each emphasised rule (any word of the lint's emphasis list in prose) becomes a plain sentence with the same content and polarity. Where the old text or project history shows which failure the rule prevents, add one sentence saying so; the anecdote goes, the reason stays. Source: the old text's own story, or the commit that introduced the rule (`git log -S '<distinctive phrase>' --oneline -- .claude src/ailsa/skills/ailsa`, at most two commit messages). - D-01: no model ID; no intended-vs-actual model comparison.
- Terms: coordinator (never orchestrator or team lead); NMR chemist; LSD engineer; solution analyst; devil's advocate, once per file as "devil's advocate (DA)" before any "DA"; diagnostic specialist. Teammate addresses `nmr-chemist`, `lsd-engineer`, `solution-analyst`, `devils-advocate` stay unchanged in the spawn calls and other code (D-04).

- History goes: phase numbers, dates, ticket IDs such as WV-07, "Bug n", "UAT", defect stories, `skill/...` pointers.
